# OpenShorts · 开片 — 架构设计（v2）

## 1. 分层

```
┌──────────────────────────────────────────────────────────────┐
│  界面层  Web Studio（Vite/React，四步流程）· 桌面端 · CLI       │
├──────────────────────────────────────────────────────────────┤
│  OpenShorts Core（本仓库）                                     │
│   templates/   口播科普 · AI 短剧 · 图层动画（v1）              │
│   sources/     画面来源适配器：stock · local · cloud · layered  │
│   voice/       TTS（Edge TTS 免费默认 → AO type:tts）          │
│   captions/    字幕（TTS 时间轴 / whisper.cpp，沿用 v1）        │
│   compose/     合成（ffmpeg；短剧走 AO concat；图层走 Remotion）│
│   publish/     封面 · 标题 · 标签 · 平台尺寸预设                │
│   cost/        花费预览（调用 AO preflight）                    │
├──────────────────────────────────────────────────────────────┤
│  agency-orchestrator（npm 依赖，不 fork）                       │
│   DAG 引擎 · 角色库 · 视频/图片/TTS 供应商表 · 看图验收 · 花费预览│
│   短剧流水线模板 · resume/feedback · doctor 探测                │
├──────────────────────────────────────────────────────────────┤
│  本机能力  ffmpeg · sd.cpp/ComfyUI（可选）· whisper.cpp（可选） │
└──────────────────────────────────────────────────────────────┘
```

**与 AO 的边界（谁做什么）**

| 能力 | 归属 | 说明 |
|---|---|---|
| 写脚本 / 分镜 / 提示词（角色、DAG、验收） | AO | OpenShorts 只提供模板 YAML 与输入 |
| 云端出图 / 出片 / TTS 供应商 | AO | `VIDEO_PROVIDERS` / `API_PROVIDERS`，一处维护 |
| 看图验收、花费预览、resume/feedback | AO | 直接复用 |
| 素材库匹配（Pexels/Pixabay） | **OpenShorts → 反哺 AO 为 `type: stock`** | 先在 OS 实现，稳定后上提 |
| 本地生成（sd.cpp 适配器） | **OpenShorts → 反哺 AO 为视频供应商 `local-sdcpp`** | 同上 |
| 口播模板、发布规格、四步界面 | OpenShorts | 产品层 |
| 图层动画（Remotion）、七道质检 | OpenShorts（v1 资产） | 作为一种来源保留 |

原则：**能进 AO 的能力都进 AO**（其他 AO 用户也受益，赞助商展示也集中），OpenShorts 只留产品层。

### 1.1 AO 的调用方式（ADR-008）
- **库调用**：`import { run, validate } from 'agency-orchestrator'` 跑模板与 preflight（同进程、拿结构化结果、SSE 由本仓库 server 转发）；`ao doctor` 探测走子进程。
- **共享配置**：直接复用 AO 的数据目录（`~/.ao`：API key、供应商、团队），用户在任一处配一次 key 两边都能用；OpenShorts 自己的设置（输出目录、素材库 key、TTS 音色）放 `~/.openshorts/config.json`。
- **版本锁定**：`agency-orchestrator@^0.19`；AO 每次发版后跑一次 OpenShorts 的契约测试（模板能 validate、preflight 字段不变）。

### 1.2 AO 运行结果 → 项目 JSON 的回填
- 模板里的脚本步骤 `output: segments_json`，要求纯 JSON（AO `assert.contains` + 解析失败返工）；回填器按 `segments[i].id` 建 `shots[]`。
- 短剧线：AO `metadata.json` 的 `steps[]` + `assets/` → `shots[]`（每镜 `visual.source = cloud|local`、`provider/model/seconds/verification`），验收结论进 `shots[].verification`，界面据此显示 ⚠️ 与"按未满足项重出"（调用 AO `feedback`）。
- 回填是纯函数 `aoResultToProject(metadata, assets, template)`，有快照测试。

## 2. 核心数据协议

沿用 v1 的 `projects/<id>.json`（版本化 JSON 是内核，界面/CLI/Agent 共读），扩展镜头的画面来源：

```jsonc
{
  "id": "kepu-001",
  "template": "koubo-kepu",            // 口播科普 | ai-drama | layered
  "line": "koubo",                      // koubo | drama
  "output": { "w": 1080, "h": 1920, "fps": 30, "platform": "douyin" },
  "script": { "topic": "…", "segments": [ { "id": "s1", "text": "…", "visualIntent": "…" } ] },
  "voice": { "provider": "edge-tts", "voice": "zh-CN-XiaoxiaoNeural", "speed": 1.0 },
  "defaults": { "visualSource": "stock" },
  "shots": [
    {
      "id": "s1", "segment": "s1", "durationSec": 4.2,       // 由配音实际时长驱动（沿用 v1 节奏重排）
      "visual": {
        "source": "stock",                                     // stock | image | local | cloud | layered
        "query": "city night traffic timelapse",               // stock 用
        "prompt": "…",                                         // image/local/cloud 用
        "provider": "pexels", "assetId": "12345", "seed": null,
        "cost": { "kind": "free" }                             // free | per-image | per-second(n)
      },
      "captions": [ { "start": 0, "end": 1.3, "text": "…" } ],
      "status": "approved"                                     // planned → ready → approved / rejected（沿用 v1）
    }
  ],
  "bgm": { "file": "…", "volume": 0.25 },
  "provenance": [ … ]                                          // 沿用 v1：每个资产的来源/模型/种子/时间
}
```

要点：
- 切来源只改 `shots[].visual`，脚本/配音/字幕不动。
- 短剧线的项目由 AO 运行结果反向生成（AO 的 `metadata.json` + `assets/` → 项目 JSON），这样界面统一。

## 3. 画面来源适配器接口

```ts
export interface VisualSource {
  id: 'stock' | 'image' | 'local' | 'cloud' | 'layered';
  /** 运行前估算：数量 / 秒数 / 是否免费（喂给花费预览） */
  estimate(shot: Shot, project: Project): CostEstimate;
  /** 产出一个镜头的画面文件（mp4 / png），带溯源信息 */
  produce(shot: Shot, project: Project, ctx: RunContext): Promise<VisualAsset>;
  /** 这台机器/这份配置能不能用（key 有没有、sd-cli 在不在、内存够不够） */
  availability(): Promise<{ ok: boolean; reason?: string; tier?: string }>;
}
```

### 3.1 stock（素材库）
- 关键词：由脚本步骤为每段输出 `visualIntent` + 英文 `query`（Pexels 英文检索更准）；同一项目内去重，避免连续两段同一条片。
- 检索顺序：本地素材夹（用户自有）→ 本地缓存 → Pexels → Pixabay；命中后按镜头时长裁切、按 9:16 智能居中裁剪（人物检测可选）。
- 失败降级：无结果 → 换关键词一次 → 退到 `image`（AI 配图）并在界面标注。
- 合规：记录 license 与作者到 provenance；发布规格里可选自动署名。
- 候选排序：每段取 3 条候选，用 AO 的看图验收员按 `visualIntent` 打分选最贴合的一条（抽中间帧交给能看图的模型；没有 vision 模型时按时长/分辨率启发式），用户可在第 3 步换另一条。
- 检索参数：`orientation=portrait`（竖版优先，其次 landscape 裁切）、`size=medium`、按镜头时长过滤 `duration >= shot`；每段最多取 3 候选供界面换片。
- 限额：Pexels 200 次/小时、20,000 次/月（免费 key）；Pixabay 100 次/分钟。本地缓存按 query 命中 7 天；批量任务串行并退避。
- key：用户自己的（界面引导注册，1 分钟）；不内置共享 key。
- 反哺 AO：稳定后做成 `type: stock` 步骤。

### 3.2 image（AI 配图）
- 直接用 AO `type: image`（供应商/模型由用户在 AO 密钥页配置），出 9:16 静帧 + Ken Burns 推拉（ffmpeg zoompan），免费素材没有合适片段时的兜底。

### 3.3 local（本地生成）
- 运行时：**stable-diffusion.cpp 的 `sd-cli`**（Metal / CUDA / CPU），不引入 Python 环境；ComfyUI 作为第二后端（有人已装时直接连 `127.0.0.1:8188`）。
- 硬件检测 → 档位表（按统一内存 / 显存）：

| 可用内存 | 推荐组合（H3） | 预期（实测/外推） |
|---|---|---|
| < 24 GB | 不提供 H3；推荐 LTX-Video 2B / Wan 1.3B（M2 待接） | 480p、分钟级 |
| 24–32 GB | `fl2va_pruned-UD-Q2_K_XL` + TE `Q2_K_M` | 640×384、1.6 s、**216 s**（M2 Max 32G 实测，ADR-004） |
| 32–48 GB | `fl2va_pruned-Q3_K/Q4_K` + TE `Q2_K_M` | 960×544、5 s、15–25 min（外推，待测） |
| ≥ 64 GB | Q4_K + TE Q4_K_M；或 h3.c 原生 Metal | 接近云端 768p 草稿 |
| NVIDIA 24 GB+ | Q4_K_M + 系统内存 ≥ 64 GB | 参考社区实测 |

- `sd-cli` 二进制：优先从 stable-diffusion.cpp 的 GitHub Releases 下载对应平台预编译包（macOS Metal / Windows CUDA·Vulkan / Linux CUDA）到 `~/.openshorts/bin/`，校验 sha256；下载不了时给出源码编译指引（本机实测 `cmake -DSD_METAL=ON` 5 分钟）。
- 模型按需下载到 `~/.openshorts/models/`，带校验与断点续传；界面明说"草稿档、约 N 分钟一条"。
- 参数：H3 固定 `cfg 1.0`、帧数对齐 `17k+5`、宽高 32 对齐；默认 4 步草稿 / 8 步精修两档。
- 反哺 AO：做成 `VIDEO_PROVIDERS` 的 `local-sdcpp`（shape: `local`），`ao doctor` 报 sd-cli 与档位。

### 3.4 cloud（云端 API）
- 完全复用 AO：`type: video` / `type: image` / `type: tts`，供应商表、探测、限速、成本预览、看图验收都在 AO。
- 短剧线就是 AO `短剧流水线.yaml`；口播线的"AI 出片"镜头是单步 `type: video`。

### 3.5 layered（图层动画，v1）
- 保留 Remotion 渲染与七道质检；作为一种来源出现在口播线的镜头级选择里（例如信息板 / 思维导图段落）。

## 4. 配音 / 字幕 / BGM / 合成
- 配音：默认 **Edge TTS**（免费、中文音色多，MPT 同款）；升级走 AO `type: tts`（OpenAI 兼容 `/audio/speech`）。
- 字幕：优先用 TTS 返回的时间戳；没有则 whisper.cpp（v1 已接本地 ASR 协议）。样式预设 3 套（抖音黄字描边 / 简约白 / 双语）。
- 节奏：**配音时长驱动镜头时长**（v1 的"旁白重排"），画面按镜头裁切，不拉伸。
- BGM：本地曲库（v1 `music` 脚本）+ 自动 ducking；短剧线走 AO concat 的 `bgm/voiceover/clip_volume`。
- 合成：口播线 ffmpeg（拼接 + 字幕 + 混音，libass 缺失时软字幕降级，沿用 AO 规则）；图层线 Remotion。

## 5. 界面（四步 + 首跑引导）

**首跑引导（只出现一次，可跳过）**：① 文本模型 key（复用 AO 密钥页，或选本地 Ollama）→ ② 素材库 key（Pexels/Pixabay 注册链接 + 粘贴 + 探活）→ ③ 试听 3 个中文音色选默认 → ④ 输出目录。每步都有"稍后再说"，跳过的项在对应步骤再提示。

| 步 | 用户看到 | 用户操作 | 系统状态 / 校验 |
|---|---|---|---|
| 1 输入 | 内容线切换（口播 / 短剧）、模板卡、大文本框（话题 / 文案 / 故事）、风格与时长档 | 填一句话即可；可粘整篇文案 | 空输入禁用下一步；字数超限提示会分段 |
| 2 来源与花费 | 项目级来源单选（素材库 / AI 配图 / 本地 / 云端）、镜头级覆盖表（脚本生成后才出现）、右栏花费预览（复用 AO preflight 文案） | 选来源；改某镜来源 | 来源不可用（无 key / 无 sd-cli / 内存不够）灰掉并说原因；有钱步骤必须展示数量级后才能运行 |
| 3 预览与调整 | 镜头列表：画面缩略 / 字幕 / 配音波形 / 时长；验收 ⚠️ 与未满足项 | 换素材候选（3 选 1）、改字幕、换来源重出单镜、按未满足项重出 | 单镜重出不改其他镜；每次重出记 provenance |
| 4 出片与发布 | 成片播放器、质检报告（七道门）、封面 3 选 1、标题 3 选 1、标签、发布说明（含 AI 标识开关） | 下载 mp4 / SRT / 封面；复制发布文案；选平台预设 | 质检未过不阻止下载但醒目标红 |

界面文案原则：不出现"工作流 / DAG / YAML"字样；所有花钱与降级的地方都说人话（沿用 AO Studio 七原则）。

## 12. CLI 与本地 API 规范

CLI（`npx openshorts <cmd>`，收敛 v1 的 20 个 npm scripts，旧命令保留别名一版）：
| 命令 | 作用 |
|---|---|
| `openshorts` / `openshorts open` | 起本地服务并开浏览器 |
| `openshorts new <模板> --topic "…" [--source stock]` | 生成项目 JSON（跑脚本步，不出片） |
| `openshorts estimate <project.json>` | 花费预览 |
| `openshorts run <project.json> [--from shot-3] [--feedback "…"]` | 出片（含配音/字幕/合成），支持从某镜重跑与带意见重出 |
| `openshorts render <project.json>` | 只合成（画面已就绪时） |
| `openshorts sources` | 列出本机可用来源及原因（key / sd-cli / 内存） |
| `openshorts doctor` | 转 AO doctor + 素材库探活 + ffmpeg/whisper 检查 |

本地 API（Express，127.0.0.1）：`GET /api/sources`、`POST /api/projects`（新建）、`GET/PUT /api/projects/:id`、`POST /api/projects/:id/estimate`、`POST /api/projects/:id/run`（SSE：step / shot / preflight / done）、`POST /api/projects/:id/shots/:sid/redo`（换来源 / 带意见）、`GET /api/tts/voices`、`POST /api/tts/preview`、`GET /api/projects/:id/artifacts/:file`。所有写操作校验路径在输出目录内；不接受 `@file` 展开（沿用 AO 的 `AO_NO_AT_FILE` 教训）。

## 13. 模板示例（口播科普，AO 工作流骨架）

```yaml
name: "口播科普"
agents_dir: "agency-agents-zh"
inputs:
  - { name: topic, label: 话题或文案, required: true }
  - { name: duration, label: 目标时长, options: ["45秒", "60秒", "90秒"], default: "60秒" }
  - { name: tone, label: 语气, options: ["科普讲解", "犀利观点", "轻松口播"], default: "科普讲解" }
steps:
  - id: script
    role: "marketing/marketing-content-creator"          # 由 AO 角色库提供；也可换成 company/chief-marketing-officer 定调
    task: |
      围绕「{{topic}}」写一条 {{duration}} 的竖版口播脚本，语气：{{tone}}。
      只输出 JSON：{"hook": "...", "segments": [{"id": "s1", "text": "...", "visualIntent": "...", "query": "english stock query", "emphasis": ["关键词"]}], "outro": "..."}
      规则：钩子 ≤ 3 秒；3–5 个要点；每段一个画面意图；query 用英文名词短语。
    assert: { contains: ["\"segments\""], min_bytes: 300, max_bytes: 4000 }
    acceptance: "1. 钩子是一句反常识或提问  2. 每段 text 口语化、可在 8 秒内念完  3. query 是具体可检索的英文画面描述，不是抽象词"
    output: segments_json
  - id: meta
    role: "marketing/marketing-douyin-strategist"
    task: "根据脚本给出 3 个标题（≤ 20 字）、5 个话题标签、一句发布说明（须含'AI 生成'标识提示）。只输出 JSON。
{{segments_json}}"
    assert: { contains: ["titles", "tags"] }
    output: meta_json
```
配音 / 素材 / 字幕 / 合成不在 YAML 里，由 OpenShorts 的 run 按项目 JSON 执行（这些是产品层能力，等 `type: stock` 上提到 AO 后再评估是否整条进 YAML）。

## 14. 协议版本与 v1 迁移
- 项目 JSON 加 `schemaVersion: 2`；读到 v1 项目（无该字段）时按 `layered` 来源解释，写回时升到 2；不做反向降级。
- `content/<id>/storyboard.json` 保留给 layered 线；口播/短剧线只用项目 JSON。
- 迁移脚本 `openshorts migrate <project.json>` + 快照测试。

## 15. 性能目标、遥测、更新
- 口播 60 秒片（素材库路径）：从点运行到 mp4 ≤ 5 分钟（脚本 ≤ 40 s、素材 ≤ 60 s、配音 ≤ 30 s、合成 ≤ 90 s，M2 Max 基线）；任务串行执行（沿用 v1 队列），云端步骤并发交给 AO。
- 遥测：**默认关**；opt-in 后只发匿名计数（模板 / 来源 / 成败），不发文案与素材（ADR-011）。
- 更新：`npx` 每次取最新；桌面端启动时检查版本并提示（复用 AO 的 `stale/latest` 逻辑）。

技术：沿用 v1 的 Vite + React + Express 本地服务；AO 作为子进程/库调用（`ao run` + SSE 或直接 `import { run }`）。

## 7. 技术选型
- Node 20+ / TypeScript；AO 作为 npm 依赖（`agency-orchestrator@^0.19`）。
- 不引入 Python；本地推理只调外部二进制（sd-cli / ComfyUI HTTP）。
- 素材库 SDK：直接 fetch（Pexels/Pixabay REST 简单，不加依赖）。
- Edge TTS：`edge-tts` 协议的 Node 实现（社区包评估后定，或自实现 WebSocket）。

## 8. 安全与合规
- key 只存本机（沿用 AO `~/.ao` 与 v1 `.env`）；服务只监听 127.0.0.1。
- 素材 license 入 provenance；引用素材沿用 v1 `assets/quoted/` 约定。
- 真人肖像 / IP 角色提示词过滤沿用 AO 创意库规则。

## 9. 各阶段的失败与降级矩阵
| 阶段 | 失败 | 处理 |
|---|---|---|
| 脚本 | 非法 JSON / 缺字段 | AO assert 返工一轮 → 仍失败：展示可编辑分段表，用户改完继续 |
| 素材库 | 无结果 / 限流 / 网络 | 换关键词一次 → 退 AI 配图（有图片供应商）→ 退纯色底+大字幕，并标注 |
| 本地生成 | sd-cli 缺 / 内存不足 / 超时 | 界面隐藏不可用档位；超时（默认 30 分钟）杀进程并建议云端 |
| 云端出片 | 404 / 限速 / 余额不足 | AO 已有：指明供应商与原因；任务已创建的绝不丢（沿用 AO 纪律） |
| 配音 | Edge TTS 端点变动 | 切 AO tts 或离线方案；字幕退回按标点估时 |
| 字幕 | 无时间戳 | whisper.cpp 对齐 → 仍无：按字数比例分配 |
| 合成 | ffmpeg 缺 libass | 软字幕轨降级（沿用 AO） |

## 10. 测试策略
- 单元：素材匹配/裁切、字幕时轴、回填器（快照）、花费预览、发布规格。
- 契约：模板对 AO 的依赖（validate 通过、输出变量名、preflight 字段），AO 升版即跑。
- 端到端（本机手动 + CI 可选）：免费路径 `话题 → mp4` 一条，用 CI secrets 的 Pexels key；云端路径只在有 key 的机器上手动跑并把成片入 README。
- 质检：沿用 v1 七道门（响度、分辨率、抽帧、字幕越界…）作为出片后的自动验收。

## 11. 发布与版本
- npm 包 `openshorts`（`npx openshorts` 入口），用 Trusted Publishing（AO 主仓已跑通的流水线照搬；角色库那次 ENEEDAUTH 的教训：npm 侧 Repository 必须填本仓库名）。
- 桌面端与 Docker 沿用 v1；版本号独立于 AO，CHANGELOG 记录依赖的 AO 版本。
