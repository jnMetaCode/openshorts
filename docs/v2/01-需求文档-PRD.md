# OpenShorts · 开片 — 需求文档（PRD v2）

版本：v2.1 · 2026-08-30 · 状态：已定案，进入 M0（v2.1：自审后补齐模板规格、免费路径前提、合规、竞品对照、用户故事）

## 1. 定位

**开源、本地优先的短视频生产线：文案进，成片出。**

- 面向中文创作者先行（界面、模板、TTS 音色、发布规格全部按国内平台），英文随后。
- 不是模型，不是剪辑器，不是 SaaS；是把"脚本 → 画面 → 配音 → 字幕 → 合成 → 发布"串成一条可控、可复现、成本透明的流水线。
- 与 [MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo)（119k★）的关系：它证明了"话题 → 素材库拼片 → TTS"这条零成本路线有海量需求；我们把这条路线做进来当**默认免费路径**，再加上它没有的：**真·AI 出片（本地 / 云端）、验收员看图把关、花费预览、一条命令或双击安装**。

## 2. 目标用户与场景

| 用户 | 典型场景 | 他最在乎 |
|---|---|---|
| 个人创作者 / 自媒体 | 每天出 1–3 条口播科普、观点、带货 | 零成本起步、10 分钟内出片、字幕好看、别被平台限流 |
| 小团队 / MCN 执行 | 批量做账号矩阵、同一脚本多版本 | 批量、模板化、稳定、可复现 |
| AI 短剧尝试者 | 想做剧情/广告片但不会 ComfyUI | 一句话出三镜、人物一致、能试本地免费再花钱 |
| 开发者 | 接进自己的流程 / 二次开发 | CLI、JSON 协议、适配器接口清楚 |

### 2.1 用户故事（M1 验收用）
- 作为自媒体新手，我输入"为什么猫爱钻纸箱"，10 分钟内拿到一条带字幕配音的竖版视频，中间只做了两次选择（模板、来源），全程 0 元。
- 作为账号运营，我把同一脚本换 3 个音色批量出 3 版，文件名和封面自动区分。（M3）
- 作为短剧尝试者，我给一段故事，先用本地免费草稿看三镜方向，满意后切云端出成片，成本在点运行前就看到。（M2）
- 作为开发者，我在 CI 里用 `openshorts render project.json` 出片，不打开界面。（M1）

## 3. 两条内容线

### 3.1 口播短视频（默认线，免费可跑通）
- 输入：话题 / 文案 / 一篇文章链接（v2 后）。
- 流程：AI 写口播脚本（分段、每段一个画面意图）→ 每段配画面 → TTS 配音 → 逐字/逐句字幕 → BGM → 合成 9:16 1080P → 导出 + 发布规格（封面、标题、话题标签）。
- 画面来源默认 **素材库**（Pexels / Pixabay 免费片段，按每段关键词匹配），可切 **AI 配图**（文生图，成本低）或 **AI 出片**。
- **"免费"的准确含义**：0 元，但不是零配置——素材库要一把免费的 Pexels/Pixabay API key（注册即得，界面一键引导），脚本要一个文本模型（用户自己的 key，或本地 Ollama），配音用 Edge TTS（免费但依赖微软非官方端点，可能变动；离线备选见 `docs/tts.md`）。产品不内置任何共享 key。
- 首个内置模板：**「口播科普」**（M1 验收标准之一），规格如下：
  - 时长 45–90 秒，6–10 段；结构固定为 **钩子（≤3 秒，一句反常识/问题）→ 正文 3–5 个要点（每点 1–2 句，一个画面意图）→ 收尾（一句结论 + 行动/关注引导）**；
  - 脚本步骤必须输出结构化 JSON（`segments[]`：`text`、`visualIntent`、英文 `query`、`emphasis` 关键词），用 AO `assert` 做结构校验，解析失败自动返工一轮；
  - 每段字幕 ≤ 16 字/行、最多 2 行；关键词高亮；口播语速 4–5 字/秒，段时长由配音实际时长决定；
  - 画面每 2–4 秒切一次（长段拆两条素材），第一镜必须是主体，不出 logo/封面卡开场（片尾放）；
  - 产出：mp4（1080×1920/30fps/H.264+AAC）、SRT、封面 PNG、标题 ×3、话题标签 ×5、发布说明（含 AI 标识）。

### 3.2 AI 短剧（差异化线）
- 输入：一段故事 / 一个创意 + 题材 + 风格。
- 流程：编剧写三镜剧本 → 主角定妆图 → 三镜提示词（5 段式）→ 图生视频三镜（以定妆图为首帧，保证人物一致）→ 看图验收（不合格重出/告警）→ 可选旁白/字幕/BGM → 合成。
- 这条流程 AO 已跑通（`workflows/短剧流水线.yaml`，真机三轮），OpenShorts 直接复用，只换一层界面。
- 画面来源：**本地生成**（草稿档，免费，画质降级）/ **云端 API**（成片档，按秒计费）。

## 4. 三种画面来源（核心抽象）

| 来源 | 成本 | 质量 | 速度 | 适用 |
|---|---|---|---|---|
| A. 素材库（Pexels / Pixabay / 本地素材夹） | 免费 | 真实拍摄 | 秒级 | 口播、资讯、观点 |
| B. 本地生成（sd.cpp / ComfyUI；H3-GGUF、LTX、Wan…按机器挑） | 免费（电费） | 草稿级～可用 | 分钟级 | 短剧草稿、抽卡验证方向 |
| C. 云端 API（秘塔 H3、火山 Seedance、Agnes、APIMart…复用 AO 供应商表） | 按秒计费 | 成片级 | 1–3 分钟 | 短剧成片、广告片 |
| D. 图层动画（v1 的 Remotion 剪纸 / 信息板） | 免费 | 风格化 | 秒级 | 讲书、技术解读、故事片 |

硬规则：
- **同一个项目可以混用来源**（口播片里第 3 段用 AI 出片，其余素材库）。
- **切换来源不改脚本、不改字幕、不改音频**，只换画面；项目 JSON 里每个镜头记录来源、供应商、模型、种子、成本（延续 v1 的溯源协议）。
- **运行前必须展示花费预览**（几条 × 几秒 × 什么档 × 哪家；免费来源标"不花钱"）——复用 AO `media/preflight.ts`。

## 5. 功能清单

### 5.1 MVP（M1，能发的第一条片）
- [ ] 口播科普模板：话题 → 脚本 → 素材库配画面 → 免费 TTS → 字幕 → BGM → 1080×1920 mp4
- [ ] 画面来源切换（素材库 / AI 配图 / 云端出片）— 项目级默认 + 镜头级覆盖
- [ ] 花费预览
- [ ] 一句话安装：`npx openshorts`（自动起本地服务并开浏览器）；桌面端/Docker 沿用 v1
- [ ] 四步界面：输入 → 选模板与来源 → 看预览与花费 → 出片/下载
- [ ] 中文界面、中文 TTS 音色（Edge TTS 免费默认，其余走 AO `type: tts`）
- [ ] 发布规格：封面图、标题 3 选 1、话题标签、平台尺寸预设（抖音/视频号/B 站/Shorts）
- [ ] 借鉴项（见 06）：素材切换频率可调；字幕字体/位置/颜色/大小/描边/背景六项可调 + 3 套预设；音色列表与实时试听；本地素材夹优先；花费预览后"确认花费"再跑；`doctor` 加 ffmpeg 路径 / `ulimit -n` / whisper 模型缓存 / 中文字体检查；内置开源中文字体

### 5.2 M2（AI 短剧线 + 本地生成）
- [ ] 「AI 短剧」模板（复用 AO 短剧流水线）
- [ ] 本地生成适配器：sd.cpp（Metal / CUDA），硬件检测 → 推荐档位 → 按需下载 GGUF → 出片；预期时长与画质在界面明说
- [ ] 看图验收结果在界面可见，一键"按未满足项重出"
- [ ] 项目历史、重跑某一镜、更换来源重出
- [ ] 输入模式加「链接」：抓取文章正文 → 脚本（借鉴 open-chat-video-editor 的 URL2Video）

### 5.3 M3（生产力）
- [ ] 批量：一份脚本 × N 个变量 / N 个音色
- [ ] 素材库缓存与本地素材夹
- [ ] 一键发布（草稿优先，不自动发）：抖音 / 视频号 / B 站，沿用 AO 多平台发布编排官思路
- [ ] 英文界面与英文模板
- [ ] 「翻译/多语配音」模板：脚本翻译 → 换音色 → 画面不动重合成（借鉴 ShortGPT）

### 5.4 明确不做（v2 周期内）
- 账号 / 云存储 / 多人协作 SaaS
- 自研推理引擎（本地生成一律接 sd.cpp / ComfyUI）
- 自动无人值守发布
- 通用剪辑器（时间线拖拽只做到 v1 已有的程度）

## 6. 非功能约束
- **本地优先**：key 只存本机；产物在本机；无遥测默认关。
- **诚实**：不猜模型 id；本地生成的画质/耗时按实测写在界面上；示例成片必须标注"由 OpenShorts 实际生成 + 来源/模型"。
- **成本可见**：任何会花钱的步骤，运行前显示数量级；不报价（价目表不在我们手里）。
- **可复现**：项目 JSON + 种子 + 供应商/模型 = 能重出同一条。
- **可降级**：ffmpeg 缺滤镜、素材库限流、供应商 404 都要有明确的降级或报错，不静默。
- **合规**：① 国内《人工智能生成合成内容标识办法》（2025-09-01 施行）要求 AI 生成内容显式标识——发布规格默认在片尾/角标加"AI 生成"显式标识并在文件元数据写入隐式标识，用户可关但默认开；② 素材 license（Pexels/Pixabay 允许商用、禁止原样转售）写进 provenance，发布说明可选自动署名；③ 提示词过滤真人肖像与 IP 角色（沿用 AO 规则）。
- **输出落点**：默认 `~/OpenShorts/<项目>/`（成片、SRT、封面、项目 JSON、溯源），可在设置里改；不写进仓库目录。

## 7. 成功指标（发布后 8 周）
- 新用户从安装到第一条成片 ≤ 10 分钟（口播科普、免费路径）
- GitHub ≥ 2k★、每周至少 1 条外部用户发布的成片被 @ 回来
- 赞助商展示位：至少一家出片供应商冠名"免费体验由 X 提供"
- AO 引擎因 OpenShorts 反向新增的能力 ≥ 3 项（预期：素材库源、Edge TTS、发布规格导出）

## 8. 风险
| 风险 | 应对 |
|---|---|
| 素材库 API 限流 / 国内访问慢 | 本地缓存 + 镜像；素材匹配失败降级为 AI 配图 |
| 本地生成体验差（糊、慢）劝退用户 | 界面明说"草稿档"；默认推荐云端出成片；按机器隐藏不可用档位 |
| 云端供应商免费额度到期 | 冠名/推荐位跟合同走，不写死"免费" |
| 与 v1 剪纸路线的用户混淆 | v1 路线改名为"图层动画"来源，文档与模板分区 |
| Edge TTS 非官方端点失效 | 抽象 TTS 接口；备选 AO `type: tts`（付费）与本地离线方案（`docs/tts.md`），失效时界面提示切换 |
| 脚本模型输出非法 JSON | `assert` + 自动修复/返工一轮；仍失败给用户可编辑的分段表 |
| 平台对 AI 内容限流/要求标识 | 默认加显式+隐式标识；发布规格随平台规则更新 |
| 模型许可证限制（H3 Community License 的地域/用途条款） | 下载前展示并确认（ADR-014）；界面不替用户判断合规，只把条款摆在眼前 |
| Windows 用户占比高但本地生成路径只在 Mac 实测 | M2 加 Windows（CUDA/Vulkan 预编译 sd-cli）实测；不实测不写"支持" |
| 文档与代码 Mac 中心化 | CI 三平台跑免费路径 E2E（Pexels key 放 secrets） |
