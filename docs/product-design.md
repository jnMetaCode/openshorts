# 产品设计：从教程流水线到开源工具

## 产品定位

PaperCut Studio 不是“AI 一键生成视频”的黑盒，而是一个把 AI 生成素材转化为可控视频工程的编排层。目标用户是希望稳定批量出片、但不愿为每条视频手写 Remotion 坐标的内容创作者和小团队。

## 核心任务

用户真正要完成的任务是：把文案转成镜头，把镜头转成分层素材，把分层素材编排为可验收、可重复渲染的成片。因此产品主路径应为：

```text
创建项目 → 拆分镜头 → 准备/生成素材 → 静态排版
→ 设置叙事权重与错峰入场 → 音频/字幕对齐 → 预览验收 → 渲染
```

## 关键决策

### 1. JSON 是产品内核

如果直接让 Agent 修改 TSX，流程很灵活但不可预测，也无法给非开发用户稳定 UI。版本化 JSON 可以被网页、CLI、Agent 和其他服务共同生成或修改，同时保留 React 组件作为高级扩展点。

### 2. 本地优先

视频素材大、隐私敏感，本地 Remotion + FFmpeg 可以做到零上传、低成本和可复现。云渲染应是后续适配器，不应成为开源 MVP 的前置条件。

### 3. 生成能力插件化

Imagegen、ComfyUI、F5-TTS、其他 TTS 的部署成本和许可差异很大。核心只接收标准图片和音频路径。适配器未来通过统一任务接口返回素材、提示词、种子和来源元数据。

### 4. 自动化必须有质量门

最容易出问题的是裁切、脚底线、角色朝向、遮挡、重复字幕和音画错帧。后续验收器应输出结构化报告，而不是只返回“渲染成功”。

## 后续工程优先级

1. 先补编辑体验：拖拽、缩放、排序、撤销和项目管理。
2. 再补音频工作流：波形、字幕切分、旁白驱动镜头时长。
3. 然后补自动质检：透明通道、边界裁切、响度、分辨率、抽帧拼图。
4. 最后接生成模型与云队列，因为它们变化最快、运维成本最高。

## v0.4 素材边界

素材处理分成三个层次：

1. **确定性本地处理**：ImageMagick 负责纯色抠图、网格拆分、安全留白和透明通道检查。
2. **可替换素材供应器**：Imagegen Agent、ComfyUI 或人工上传只负责产出标准图片。
3. **统一入库**：所有结果进入 `public/uploads`，再由项目 JSON 引用，生成服务不能直接修改时间线。

角色素材表在抠图时默认保留画布，避免裁边后破坏网格；拆成独立角色时才自动裁边并增加 12px 透明安全边距。这样既保持拆分准确，也避免发冠、手脚和阴影贴边。

## v0.5 生产系统

单条视频工具扩展为生产系统时，项目、模板和任务必须分离：

- **项目**保存用户当前可编辑事实。
- **模板**只负责创建项目，后续升级模板不会隐式修改既有项目。
- **批量变量**在进入队列时生成项目快照，保证排队期间继续编辑不会改变待渲染结果。
- **任务**保存完整项目快照、状态、尝试次数、输出和错误；运行中断不会丢失上下文。

任务采用串行消费。对于本地创作者工具，可预测的内存占用比最大吞吐量更重要；未来云渲染适配器可以根据机器资源实现独立并发策略。

## v0.7 文案规划器

规划器的输出是结构化 storyboard，而不是直接写 Remotion 代码。这样同一份规划既能生成素材需求单，也能组装项目 JSON，还能在未来交给不同 LLM 重写。

确定性规划器负责稳定底线：切句、合并、时长、字幕区间、镜头类型轮换和四类素材需求。LLM 适配器未来只优化镜头语义和提示词，不应绕过协议校验。

角色一致性采用显式“角色圣经”：名称、年龄、服饰、发型、配色和标志物。人物提示词必须携带完整锚点；生成结果仍需人工在策划台确认后才能替换时间线素材。

## v0.8 可追踪生产

- 分镜规划器采用适配器协议，本地规则引擎提供稳定底线，OpenAI 兼容接口只优化镜头语义。
- 每项素材计划保留提示词版本、激活版本、素材状态和最终路径，便于复现生成过程。
- 生成素材优先按计划 ID 匹配，其次使用镜头和角色权重，避免错误覆盖其他镜头。
- 图层关键帧直接进入项目协议，网页预览与 Remotion 最终渲染共用同一套插值逻辑。

下一阶段重点是素材审核看板、生成参数和种子溯源，以及旁白自动对齐后的节奏重排。

## v0.9 素材审核与节奏重排

素材从生成到进入成片必须经过 `planned → ready/assigned → approved` 状态流；退回素材进入 `rejected`，审核历史不会被覆盖。供应器、模型、种子、工作流和参数与素材计划绑定，使复现不依赖任务队列日志。

旁白重排读取每个本地音频的实际时长，并同比调整镜头时长、字幕区间、入场延迟和关键帧位置。这样更换配音后不会出现字幕被截断或动画仍按旧节奏运行的问题。

## v1.0 开源发布版

音频上传后由 FFmpeg 生成波形，ASR 通过无 shell 的本地命令适配器输出统一 JSON。分段和逐字时间戳进入项目协议，Remotion 根据当前帧高亮字词，质量检查器验证逐字区间没有越过字幕和镜头边界。

发布物提供 Docker、Compose、CI、变更日志、安全说明和贡献约定。默认服务仍只监听本机；容器显式使用 `0.0.0.0`，部署到非可信网络前必须增加认证和 TLS。

## 不建议的方向

- 不要把提示词写死为“唐朝”；风格应是模板，叙事层级才是核心协议。
- 不要承诺完全自动排版；人物朝向和遮挡仍需要可视化人工确认。
- 不要让模型直接生成带主角的完整背景；这会破坏后续可编辑性。
- 不要一开始做多人 SaaS；项目、权限、存储、计费会掩盖核心创作体验。
